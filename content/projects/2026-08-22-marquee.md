**The problem.** Checking what's playing, or skipping a track, normally means switching over to Apple Music or Spotify. Marquee puts that information and the playback controls right in the menu bar, glanceable and clickable, without leaving what you're doing.

**What it does.** A macOS menu bar app that shows the current track from Apple Music or Spotify, with a scrolling title and playback controls, inline. No popover, no extra click.

**Technical highlights.** It drives Apple Music and Spotify through ScriptingBridge (KVC), running on a background serial queue so the UI never stalls on Apple Event IPC. Updates arrive in real time via Distributed Notifications, with low-frequency polling as a backup. The menu bar view itself is custom AppKit: a two-copy ticker that scrolls seamlessly, with a timer that only runs while a track is playing, on-screen, and the display is awake. One real edge case in ScriptingBridge: a stopped-but-running source app returns a non-nil "empty" track object instead of nil. Naively, that looked like a track named "Unknown Track" was playing. The fix keys off `isPlaying()` instead of checking for a blank title alone.

**Decisions & tradeoffs.** Click-to-open uses `NSClickGestureRecognizer` instead of a `mouseDown` override. `mouseDown` fires on press, which would collide with the right-click context menu on a control-click; the gesture recognizer avoids that. It ships ad-hoc signed, not notarized, a deliberate tradeoff against cost and complexity. Users have to manually clear Gatekeeper quarantine on first install. It's distributed through a personal Homebrew tap, a separate repo, instead of the Mac App Store: a self-hosted pipeline of build script, zip, GitHub release, then a tap cask update.

**Outcome / status.** Shipped and public: first commit 2026-07-13, tagged releases v1.0.0 and v1.0.1, latest push 2026-08-19. Distributed via `brew install --cask bilal-psd/tap/marquee`. GitHub shows 0 stars. It's a personal-use tool, not something pushed for visibility.
